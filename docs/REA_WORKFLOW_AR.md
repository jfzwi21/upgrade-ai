# دليل دمج واستخدام أداة REA (Reverse Engineering Assistant) بالعربية العراقية

هذا الدليل يشرح بالتفصيل وبلهجة عراقية واضحة ومباشرة شنو هي أداة **REA**، وشلون تكدر تستفاد منها بسير عمل المشروع (Workflow)، والحدود التقنية والأمنية لدمجها.

---

## 1. شنو هي أداة REA بالضبط؟
أداة **REA** (من مستودع `morluto/rea`) هي **خادم MCP (Model Context Protocol) وواجهة سطر أوامر (CLI)** مخصصة لبيئات سطح المكتب (Desktop Workstations) وللمساعدين البرمجيين (مثل Cursor، Claude Code، وGemini CLI).
وظيفتها الأساسية:
- مساعدة المطور ومهندس الأمان على **الهندسة العكسية وتحليل الملفات الثنائية (Binaries)**.
- تشغيل وتنسيق أدوات التحليل المحلية العميقة:
  - **Ghidra** و **Hopper Disassembler** و **IDA Pro**.
  - أدوات سطر أوامر مثل **objdump** و **readelf** و **nm** و **GDB**.
  - أدوات تحليل دوت نت مثل **ilspycmd** وغيرها.
- توفير تحكم منظم (Tools & Resources) للذكاء الاصطناعي لفحص كود التجميع (Assembly)، وتتبع استدعاءات الدوال، والتحقق من التواقيع وهياكل البيانات.

> **تنبيه مهم جداً:** أداة REA **ليست محرك استدلال (Inference Engine)**، وليست مكتبة لتشغيل نماذج اللغة، ولا تعالج الهلوسة بحد ذاتها؛ هي أداة تحليل وهندسة عكسية فقط.

---

## 2. هل تكدر تشغل REA داخل تطبيق الأندرويد (APK) أو بيئة AI Studio الحالية؟

### أولاً: داخل الـ APK للأندرويد:
**مستحيل تقنياً وغير آمن.** والسبب:
1. بيئة أندرويد (Android Sandbox) ما تحتوي على بيئة Node.js 22+ ولا تدعم تشغيل خوادم MCP داخل حزمة التطبيق.
2. أدوات REA تعتمد على برامج أصلية لسطح المكتب (Ghidra, Hopper, IDA, Desktop GDB) وهي غير متوفرة داخل بيئة هواتف أندرويد المحمولة.
3. حزم هذه الأدوات داخل الـ APK راح يضخّم حجم التطبيق بمئات الميجابايتات بدون أي فائدة للمستخدم العادي، فضلاً عن رفض متجر Google Play لمثل هذه الأدوات.

### ثانياً: داخل بيئة Google AI Studio:
- بيئة AI Studio هي بيئة حاوية (Container) مخصصة لبناء ومعاينة تطبيقات أندرويد، ولا تدعم فتح منافذ خادم MCP محلي موجه للعميل.

### التوصية المعمارية الصحيحة (Recommended Architecture):
دمج REA يكون **حصراً على جهاز المطور (Workstation) أو في خط أنابيب التطوير والـ CI**، واستخدام مخرجاتها كـ **وثائق مرجعية سلبية (Reference Documentation)** تُضاف لقاعدة معرفة المساعد العراقي عند الحاجة لتحليل ملفات المشروع الخاصة.

---

## 3. المتطلبات الأساسية لتشغيل REA
قبل ما تبدأ، تأكد من توفر الآتي على حاسوبك الشخصي:
- **Node.js**: إصدار حديث (`v22.23.4` أو `v24.22.1` فما فوق).
- نظام تشغيل: Linux أو macOS أو Windows (عبر WSL2).
- توفر أداة تحليل واحدة على الأقل مثبتة وموجودة بالـ `PATH` (مثل `objdump`، `readelf`، أو `ghidra`).

---

## 4. خطوات التثبيت والإعداد خطوة بخطوة

### الخطوة الأولى: فحص إصدار Node.js
افتح الطرفية (Terminal) واكتب:
```bash
node -v
```
لازم يكون الناتج يبدأ بـ `v22` أو أعلى.

### الخطوة الثانية: تثبيت وإعداد وكلاء REA
استخدم أمر `npx` المباشر بدون الحاجة لتثبيت عام يدوي:
```bash
npx rea-agents setup
```
هذا الأمر راح يسألك عن المساعد البرمجي اللي تستخدمه (مثلاً Claude Code أو Cursor)، ويثبت ملفات الإعداد الخاصة بـ MCP تلقائياً في مسار الإعداد:
- للـ Cursor: يضيف الإعداد بملف `~/.cursor/mcp.json` أو إعدادات المشروع `.cursor/mcp.json`.
- للـ Claude Desktop / Code: يضيف الإعداد بملف `claude_desktop_config.json`.

### الخطوة الثالثة: تشغيل فحص سريع للـ CLI
للتأكد إن كل شي شغال:
```bash
npx rea --help
```

## 5. أمثلة عملية لاستخدام REA في تطوير مشروع Upgrade AI

### مثال 1: فحص الرموز والمكتبات المشتركة (Shared Libraries .so)
إذا بنيت مكتبة `llama.rn` أو مكتبة C++ خاصة بالتطبيق، وتريد تتأكد من الدوال المصدّرة:
```bash
npx rea inspect android/app/build/intermediates/merged_native_libs/release/out/lib/arm64-v8a/libllama.so
```

### مثال 2: التأكد من عدم وجود تسريب لرموز التصحيح (Debug Symbols)
قبل نشر نسخة الـ Release:
```bash
npx rea symbols android/app/build/outputs/apk/release/app-release.apk
```

## 6. ضوابط الأمان والاستخدام المسؤول
1. **الملكية والتصريح:** استخدم REA **فقط** لفحص ملفات مشروعك وتطبيقاتك الخاصة، أو البرمجيات التي تمتلك إذناً رسمياً وصريحاً باختبارها وتحليلها.
2. **عدم كسر الحماية:** يُمنع منعاً باتاً استخدام الأداة لتجاوز أنظمة حماية حقوق الملكية (DRM)، أو برامج مكافحة الغش (Anti-Cheat)، أو الوصول غير المصرح للبيانات.
3. **معاملة المخرجات كبيانات غير موثوقة:** نتائج التفكيك والتحليل الصادرة من الأداة هي نصوص ومعطيات للتحليل فقط وليست تعليمات برمجية ينفذها النظام تلقائياً؛ لا تدع أي نموذج ذكاء اصطناعي ينفذ كود ناتج بدون مراجعة بشرية صريحة.
4. **حفظ حقوق النشر والترخيص:** أداة REA مرخصة برخصة MIT (Copyright (c) 2025 morluto). يجب الحفاظ على إشعار الترخيص وحقوق المؤلف كما هي دون حذف.

## 7. كيفية إيقاف أو إزالة أداة REA بالكامل
إذا خلصت شغلك وتريد تنظف إعدادات الـ MCP من حاسوبك:
```bash
npx rea-agents remove
```
هذا الأمر يمسح إدخالات خادم REA من ملفات إعداد MCP ويرجع كل شي مثل ما كان بدون أي بقايا.
